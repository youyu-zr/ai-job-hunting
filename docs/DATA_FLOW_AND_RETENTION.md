# 数据流与留存现状

本文按当前候选源码记录已能确认的数据路径，不代表生产服务器日志、数据库和模型供应商留存行为已经审计。线上新用户安装暂停；不要用真实简历验证下述流程。

## 浏览器到服务端

- 用户脚本在登录后的 BOSS 页面读取账号 UID、页面 token 和附件简历标识。
- 简历附件由浏览器从 BOSS 下载，再通过 `/api/user/import/resume` 上传到配置的后端。
- 后端先向 BOSS 校验 token 与 UID 的归属，再解析简历。解析后的文本写入 `user_resume.resume_content`，用户联系方式可能写入 `user_info`。
- 新账号候选流程要求用户主动点击“导入简历”；截至 2026-10-10 线上仍为 `0.0.113-beta-auto-grant`。线上首次登录自动导入行为此前已核验，本次复核确认安装页和脚本仍未切换到候选版本。
- 后续岗位分析和 HR 沟通会使用简历、岗位、偏好和会话上下文；实际传输范围取决于所配置的 AI 服务。

## 第三方服务

简历本地解析不可用时，后端可能把简历文件交给部署者配置的文件解析模型。岗位分析、生成消息或会话处理也会把相应上下文发送到部署者配置的模型服务。用户自定义模型地址由后端请求；当前代码尚未对公网共享实例建立充分的 SSRF/出网隔离。

使用维护者托管实例前，必须先明确运营者、实际模型供应商、传输字段、处理地区、供应商留存条款和可联系的数据删除渠道。当前尚不能提供已核实的完整清单。

## 模型 Key 边界

- 普通用户使用维护者托管服务时，不需要在浏览器或脚本中填写模型 API Key；维护者配置的全局模型 Key 应由服务端运行环境或服务端私有配置读取。仓库中的示例只包含环境变量占位符，不应放入真实值。
- 当前源码和 Git 历史的启发式检查未发现可确认的真实模型 Key、访问令牌或私钥；这不是对 OVH 当前环境、备份或 GitHub 扫描结果的证明。本轮没有读取生产环境变量。
- 用户自定义模型 Key 的后端接口会将 Key 保存到 `user_ai_config.api_key`，数据库字段当前是明文存储。查询配置时接口会隐藏 Key 原文，但这不能保护数据库、备份或运维导出。
- 普通托管用户无需配置自定义 Key。面向共享实例开放用户自带 Key 前，应先完成前端路径、服务路由、数据库加密、轮换和删除策略的复核。
- 自部署用户应把自己的 Key 放在环境变量、私有配置或密钥管理工具中；不得写入源码、公开 Issue、PR、构建产物或截图。

## 留存与删除

- 应用数据库会保存解析后的简历文本、用户配置和消息会话数据。
- 当前仓库没有自助删除账号及所有关联数据的 API，也没有可由代码证明的统一自动删除期限。
- 候选代码将简历替换改为更新同一条唯一记录，不再先逻辑删除后插入；这避免重复导入撞唯一索引，但不等于账号删除，也不覆盖历史备份、日志或模型供应商副本。
- 生产数据库、备份、Nginx/系统日志和第三方供应商的实际留存时长，本次没有读取或核验。

因此，在建立并演练完整的数据访问、删除、备份到期清除和供应商删除流程之前，不要招募公众上传真实简历。对高敏感用户资料，优先等自部署经过干净环境验证后再使用，并自行管理数据库及模型服务。

## 发布前必补

1. 明确数据控制者/运营者、收集目的、必要字段、处理依据、联系渠道和用户权利说明。
2. 给出各数据表、日志、备份和模型供应商的可核验保存期限及删除步骤。
3. 实现并测试账号删除和关联数据删除，避免只删除简历行却保留会话或标识信息。
4. 核验共享实例的文件上传大小、频率、并发和模型日预算；候选代码已有单实例限速与并发闸门，但没有分布式限流或模型日额度。
5. 候选代码已加入模型 URL、DNS 解析 IP 和重定向防护；生产仍须以出网防火墙阻断私网及元数据地址，不能只依赖应用层检查。
6. 用脱敏数据演练一次完整导入、删除和备份到期清理，再恢复真实用户试用。
