# 数据流与留存现状

本文描述源码候选 `0.0.120-beta-resume-auth` 的数据路径与限制，不代表生产服务器日志、数据库和模型供应商留存行为已经完整审计。截至 2026-10-21，只读核验的线上安装页仍为 `0.0.119-beta-resume-import`；`0.0.120` 尚待合并、部署及真实 BOSS 账号验收。真实账号验收完成前不应扩大使用。

## 浏览器到服务端

- 用户脚本在登录后的 BOSS 页面读取账号 UID 和当前 `bst` Cookie，用于静默登录；登录流程不会读取附件简历。
- 服务端向 BOSS 验证 UID 与 token 归属，验证通过后创建空用户档案并授予有效期内的内测权限。
- 静默登录成功后，服务端签发 AI 工作猎手应用会话。简历导入前，浏览器确认当前 BOSS UID、Cookie、服务器地址与该应用会话相符；首次点击导入时会先尝试建立应用会话。
- 用户主动导入时，浏览器使用 BOSS 登录凭据读取附件列表并下载附件，再将文件和简历 ID 连同应用 `Authorization` 会话上传到 `/api/user/import/resume`。
- 导入接口要求有效的应用会话。服务端从该会话取得用户 ID 并据此保存，不采用客户端提交的 BOSS UID 来选择保存账户，也不在导入请求中再次向 BOSS 验证 token。服务端应用会话缓存最长约两小时；因此 BOSS 登出后，已签发且尚未过期的应用会话仍可访问同一服务端账户。浏览器中的正常导入按钮还会检查当前 BOSS 身份是否变化。
- 简历解析后的文本写入 `user_resume.resume_content`，识别出的联系方式可能写入 `user_info`。简历导入是用户主动操作，不是创建账号或开通内测的前置条件。
- 后续岗位分析和 HR 沟通会使用简历、岗位、偏好和会话上下文；实际传输范围取决于所配置的 AI 服务。

## 候选版本的判断与执行边界

在 `0.0.117` 联调版中，浏览器脚本从 BOSS 页面读取职位与消息、提供发送者和协议类型等元数据，并执行经服务端决策后的页面操作；服务器 AI 结合岗位上下文、简历和已保存偏好判断岗位与 HR 消息含义。普通推广默认静默，用户可编辑普通推广偏好；明确高风险不受该偏好放行。普通岗位缺少薪资、城市等信息且没有明确风险或已填偏好冲突时，继续投递并把问题留给后续沟通。模型/API/格式故障时不自动投递或发送。

薪资、地点和联系方式按用户已保存偏好判断；未填写时视为未知，不自动接受、拒绝或透露联系方式。具体面试日期/时间及平台面试卡片需要本人确认，只交还当前会话。BOSS 的结构化系统事件可能显示在聊天界面，但不是 HR 消息；按协议元数据识别，不以普通文本关键词代替协议判断。

上述是处理设计和实现说明，不是准确率、真实账号兼容性或生产验收结论。岗位与消息上下文发送到服务器和配置的模型服务，具体字段按功能请求而异；本段不替代对生产日志或供应商留存的独立核验。

## 第三方服务

简历本地解析不可用时，后端可能把简历文件交给部署者配置的文件解析模型。岗位分析、生成消息或会话处理也会把相应上下文发送到部署者配置的模型服务。用户自定义模型地址由后端请求；当前代码尚未对公网共享实例建立充分的 SSRF/出网隔离。

使用维护者托管实例前，必须先明确运营者、实际模型供应商、传输字段、处理地区、供应商留存条款和可联系的数据删除渠道。当前尚不能提供已核实的完整清单。

## 模型 Key 边界

- 普通用户使用维护者托管服务时，不需要在浏览器或脚本中填写模型 API Key；维护者配置的全局模型 Key 应由服务端运行环境或服务端私有配置读取。仓库中的示例只包含环境变量占位符，不应放入真实值。
- 当前源码和 Git 历史的启发式检查未发现可确认的真实模型 Key、访问令牌或私钥；这不是对 OVH 当前环境、备份或 GitHub 扫描结果的证明。本轮没有读取生产环境变量。
- 用户自定义模型 Key 的后端接口会将 Key 保存到 `user_ai_config.api_key`，数据库字段当前是明文存储。查询配置时接口会隐藏 Key 原文，但这不能保护数据库、备份或运维导出。
- 普通托管用户无需配置自定义 Key。面向共享实例开放用户自带 Key 前，应先完成前端路径、服务路由、数据库加密、轮换和删除策略的复核。
- 自部署用户应把自己的 Key 放在环境变量、私有配置或密钥管理工具中；不得写入源码、公开 Issue、PR、构建产物或截图。

## 留存与删除

- 应用数据库会保存解析后的简历文本、用户配置和消息会话数据。
- 当前仓库没有自助删除账号及所有关联数据的 API，也没有可由代码证明的统一自动删除期限。
- 候选代码将简历替换改为更新同一条唯一记录，不再先逻辑删除后插入；这避免重复导入撞唯一索引，但不等于账号删除，也不覆盖历史备份、日志或模型供应商副本。
- 生产数据库、备份、Nginx/系统日志和第三方供应商的实际留存时长，本次没有读取或核验。

因此，在建立并演练完整的数据访问、删除、备份到期清除和供应商删除流程之前，不要招募公众上传真实简历。对高敏感用户资料，优先等自部署经过干净环境验证后再使用，并自行管理数据库及模型服务。

## 发布前必补

1. 明确数据控制者/运营者、收集目的、必要字段、处理依据、联系渠道和用户权利说明。
2. 给出各数据表、日志、备份和模型供应商的可核验保存期限及删除步骤。
3. 实现并测试账号删除和关联数据删除，避免只删除简历行却保留会话或标识信息。
4. 核验共享实例的文件上传大小、频率、并发和模型日预算；候选代码已有单实例限速与并发闸门，但没有分布式限流或模型日额度。
5. 候选代码已加入模型 URL、DNS 解析 IP 和重定向防护；生产仍须以出网防火墙阻断私网及元数据地址，不能只依赖应用层检查。
6. 用脱敏数据演练一次完整导入、删除和备份到期清理，再恢复真实用户试用。
