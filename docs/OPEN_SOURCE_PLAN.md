# 开源与推广方案

## 判断

“全部开源 + 抖音宣传 + 公开 PR 共建”可以走，而且适合这个项目。但顺序应是：先让别人看懂、能启动、能安全试用，再让更多人知道。

真正应该全部公开的是可复现的软件、测试和决策边界，不是生产数据库、个人简历、Cookie、SMTP 密码、AI Key、激活码和运行日志。所谓“全部开源”应理解为软件实现、测试、文档和问题处理过程全部公开，不等于公开凭据、用户数据和生产基础设施。

## 两类用户的正式路径

### 普通求职者

普通用户使用维护者提供的托管实例，不需要申请或填写自己的模型 API Key。用户仍需安装脚本管理器、登录自己的 BOSS 账号，并在页面中主动确认简历导入。托管服务不是纯本地运行，简历、岗位和会话内容的实际传输范围以实例的数据说明为准。

### 高级用户和开发者

高级用户拉取源码后自行配置数据库、模型服务和部署环境。自部署实例需要使用者自己的模型 Key，凭据只放在环境变量、私有配置或密钥管理服务中，不写入源码。开发者可以提交文档、测试、页面兼容修复和代码 PR。

不要把“普通用户不用 Key”和“自部署开箱即用”混为一谈，也不要宣传当前版本已经完整支持托管模式与用户自带 Key 的自动混合路由；这一点仍需产品代码与前端入口单独验收。

## 产品定位

> 一个运行在 BOSS 直聘网页中的开源 AI 求职副驾：帮你筛岗位、写第一句话、整理沟通上下文，并在关键决定前把控制权交还给你。

这比“替你海投的机器人”更准确，也更符合当前真实能力。

## 与现有产品的区别

因此定位不应是“功能最多的 AI 求职平台”，而是“BOSS 直聘网页内、以中文 HR 沟通为中心、重视可观察发送状态和人工接管的开源求职副驾”。

开源与自部署目前仍是目标和代码边界，不等于已经有稳定安装、干净机器部署、长期维护和隐私审计的成熟社区产品。真实账号验收没完成前，不宣传转化率、面试提升率或发送成功率。

与招聘平台官方 AI 功能比较时，只比较公开可验证能力；不宣称官方没有某项功能，除非做过有日期的产品核验。

本表是 2026-10-08 的公开产品页核对，不代表各产品在所有地区、账户或灰度版本都开放相同功能。核对入口：[Teal Job Tracker](https://www.tealhq.com/tools/job-tracker)、[Simplify Copilot](https://simplify.jobs/copilot)、[Simplify AI Talent Agent](https://simplify.jobs/ai-talent-agent)、[Jobright](https://jobright.ai/)。

## 抖音内容

优先做真实开发和真实失败复盘：

1. 岗位筛选、岗位化首句和人工接管演示；
2. 为什么“已提交”不等于“已发送”；
3. 账号接管、CORS 和跨账号串号问题如何被发现和修复；
4. 一个 PR 如何新增协议回归测试；
5. 如何安全设置低风险岗位和人工确认。

第一阶段的转化目标不是让陌生人立刻批量投递，而是：

- 看懂项目边界；
- 安装或自部署成功；
- 用一个低风险岗位完成一次可观察测试；
- 提交一个脱敏问题或回归测试；
- 最终形成公开 Issue、PR 和版本记录。

不要以“日投几百份”作为核心宣传，也不要把用户引导到私聊交付激活码。

## PR 机制

第一批适合外部贡献的任务：脱敏岗位样本、消息解析测试、BOSS 页面兼容性记录、UI 错误态、Docker/本地启动文档、CI 和测试覆盖。

涉及真实账号、生产部署、激活码、支付、Cookie 或聊天记录的任务暂不开放。

每个行为修复必须带回归测试；没有真实 BOSS 验收的 PR 不能标记为线上已验证；涉及发送、账号、权限和隐私的 PR 需要维护者复核。

Issue 用于问题、需求和讨论；PR 用于把 Fork 或分支中的修改提交给维护者审阅。仓库应保持 Issues 开启，并补充 Issue 模板、PR 模板、CI 和 main 分支保护。PR 不需要贡献者额外申请一个开关。

## 路线

1. 源码公开可读：统一版本，清理个人数据和生产配置；
2. 源码公开可运行：提供示例配置、Docker Compose、CI 和脱敏演示数据；
3. 小范围协作：邀请 3 到 5 位开发者，用单账号低风险岗位试用；
4. 公开宣传：用抖音展示真实能力、限制和贡献入口；
5. 根据真实失败样本继续修复协议兼容性。

## 现在不该做的事

- 不要在身份校验未知时继续放行陌生用户；平台回执不可用应拒绝登录或进入人工处理。
- 不要把“源码已公开”说成“普通用户现在就能安全使用”；当前线上脚本与本地开源准备版不是同一个发布物。
- 不要在真实账号验收、数据流说明、平台规则审查和回滚方案完成前，用抖音导入大量陌生用户到同一个托管实例。
- 不要在未确认历史 Git 对外可见内容前推送整理结果；新 README 不会删除旧提交中的部署记录。
- 仓库级 MIT 文件已在本地准备，但上游 LICENSE 获取失败，逐文件来源、版权、NOTICE 和依赖许可尚未核验；完成前不得宣称整个仓库的 MIT 授权已确认或进行公开发行。生产服务、用户数据、Cookie、模型 Key 和服务器权限不属于开源内容。

核心指标应包括首条消息确认率、未确认发送比例、HR 有效回复率、误过滤率、暂停后旧回复泄漏次数和外部 PR 合并数量。
