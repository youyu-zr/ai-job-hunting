## 本轮实际修改

- 浏览器不再用推广关键词替代服务端语义判断；正常抖音、市场、销售等岗位不会只凭名称被过滤。
- 普通岗位资料不全时继续投递并保留待问问题；模型、网络或格式故障不执行自动投递或回复。
- 模型必须返回一个完整的岗位决策；多结果、重复字段、尾部内容等不能只取前半段放行。高风险优先于旧动作兼容。
- 分类要求本人确认时，在生成回复或交换简历之前暂停当前会话；不能因没有命中某个固定词而忽略确认动作。
- 临时失败释放消息去重占位，避免恢复后误认为已经处理；暂停、建会话和恢复共用账号行锁，避免产生多个活动会话。
- 推广默认不回复；只有服务器保存了本人允许回复的偏好，且分类允许回复时，普通推广才进入后续流程。明确高风险不受该开关放行。
- 日志不再记录模型结果全文；邮箱脱敏改用线性扫描，不再依赖存在性能告警的邮箱正则。
- 消息分类区分“资料没填全”和“意图不清楚”；普通录用、签约承诺需要本人确认，但不等于招聘欺诈。普通推广的允许与拒回偏好分别处理。
- 无效 JSON 只允许追加一次完整重分类，使用原始输入，不重放模型错误文本；两次结果都必须经过同样的严格校验。有效语义判断不会为了获得某个答案而重试。
- 分类和岗位筛选使用独立请求的温度参数 0，降低随机性，不修改聊天、开场白、会话或共享客户端默认值。明确风险优先于本人确认，本人确认优先于普通信息不足；温度 0 不保证模型永不误判。
- 下载页、内置帮助和使用说明按 `0.0.117` 更新，保留三个安装入口、自动开通和主动导入简历的区分。
