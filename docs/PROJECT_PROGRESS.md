1. 先完成并行中的 Task 4/6 和代码复核；
2. 运行当前候选完整前后端测试、构建、发布检查及对抗性审查；记录哪些检查被并行改动阻断；
3. 给 `release/open-source-20261011` 加保护，再推送当前确切候选并确认 PR 指向新 head；
4. 等待该 head 的 CI/CodeQL、维护者审核和合并；旧 head 的检查不计入；
5. 核实 BOSS 当前授权边界，并由账号本人完成真实账号流程验收；
6. 全部门槛通过后，备份线上产物、原子部署、只重启目标应用服务并复核线上版本/哈希，保留回滚方案。
