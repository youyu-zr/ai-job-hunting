# AI 工作猎手

一个运行在 BOSS 直聘网页里的开源 AI 求职副驾：辅助筛岗位、生成岗位化首句、整理 HR 沟通上下文，并在关键决定前把控制权交还给你。

本项目有两种使用方式：

- **普通求职者**使用维护者提供的托管服务，不需要自己申请或填写模型 API Key；安装浏览器脚本、登录自己的 BOSS 账号后使用。
- **高级用户和开发者**拉取源码、自部署数据库和模型服务、二次开发，再通过 GitHub Issue 和 Pull Request 共同改进。

“托管模式不用自备模型 Key”不等于“完全本地运行”。简历导入后会发送到当前实例的服务端处理；使用前请阅读[数据流与保留说明](docs/DATA_FLOW_AND_RETENTION.md)。

## 如何开通

**候选版不需要激活码，也没有可公开分享的通用激活码。**候选版首次打开只检查当前 BOSS 登录身份，不会自动获取或上传附件简历；安装脚本或点击“连接测试”也不会单独创建内测权益。

1. 登录自己的 BOSS 账号并安装本脚本；
2. 在 BOSS 页面打开 AI 工作猎手面板，主动点击“导入简历”；
3. 服务端核验当前 BOSS 身份，并在简历成功解析、保存后自动创建内测权益；
4. 到“产品权限”查看开通状态和有效期。

如果简历导入失败，系统不会授予新权益。请先在 BOSS 上传附件简历，再检查登录状态和网络后重试。“邀请码”仅用于可选的邀请关系功能，不是激活码，也不是开通内测的必需条件。不要向任何人索取或发送 Cookie、简历原件或账号凭据。

## 普通用户怎么用

正式安装入口和开放状态以本页顶部为准。托管模式下不需要填写自己的模型 Key，但需要安装浏览器脚本管理器、登录自己的 BOSS 账号，并在面板中主动点击“导入简历”。第一次使用建议先用一个低风险岗位观察筛选、生成和发送状态。

AI 帮你减少重复操作，不替你决定是否投递，也不替你承诺面试、联系方式、薪资、到岗或录用。当前安装和试用是否开放，以线上版本与下方项目状态为准。

## 开发者怎么参与

**Issue** 用来报错、提需求或记录页面兼容性；先搜索已有问题，再写脱敏复现步骤。

**Pull Request（PR）** 是把你在自己副本里完成的代码、测试或文档修改提交给维护者审阅：

1. Fork 本仓库，在自己的副本创建分支；
2. 修改代码、文档或测试，写清实际验证结果；
3. 在 GitHub 选择 **New pull request**，将改动提交给本仓库的 `main`；
4. 维护者讨论、复核后决定是否合并。

PR 不需要单独申请“开通”。仓库允许 Fork，Issues 已开启。涉及发送、身份、权限、简历和隐私的改动必须带测试并由维护者复核。

## 开发与贡献

前端需要 Node.js 24 和 pnpm，后端需要 JDK 17 和 Maven。先按子目录说明运行测试，再提交 PR。不要把真实简历、Cookie、聊天记录、API Key、SMTP 或生产部署信息作为复现材料。

计划优先处理脱敏样本、解析回归测试、UI 错误态、自部署验证和依赖可复现性。当前工作区的候选源码尚未同步到公开主分支，完整开源许可证和发布门槛仍未确认；正式邀请外部贡献前会先发布可审阅的源码与协作规则。涉及发送、身份、授权和人工接管的修改必须由维护者复核。

## 自部署与数据

安装脚本默认连接维护者的托管服务，不是纯本地运行。岗位、简历文本、偏好和会话内容可能进入后端及配置的模型服务；请先阅读[数据流与保留说明](docs/DATA_FLOW_AND_RETENTION.md)。当前没有自助删除账号及其全部数据的功能，删除流程和时限尚未确认；不接受真实用户试用前，必须先建立可执行的数据删除流程并核验线上留存范围。

候选版可自部署，但干净机器依赖解析和真实 BOSS 流程仍未验收。当前新用户托管试用暂停；当前版本暂不提供付费服务，历史支付代码默认关闭。公开服务上线前仍需完成数据删除/保留策略、模型数据传输说明、SSRF/出口限制、限流/费用上限及真实账号验收。
