# AI 工作猎手

在 BOSS 直聘网页里，帮你筛选岗位、结合简历写开场白，并协助回复 HR 消息。你决定找什么工作，也可以随时接手聊天。

## 下载安装

- **想直接使用**：[打开安装页](https://aijob.zxpnb.top/install.html)，用电脑上的 Chrome 或 Edge 按三步安装。
- **安装后不知道怎么用**：[查看使用说明](docs/USER_GUIDE.md)。
- **遇到问题**：[反馈问题](https://github.com/youyu-zr/ai-job-hunting/issues)，写清卡在哪一步，截图请遮住私人信息。
- **想修改或自己部署**：往下看“开发者参与”，不用先研究开发文档才能安装使用。

## 安装只要三步

1. 安装脚本猫（ScriptCat）。已经使用 Tampermonkey（篡改猴）的，二选一即可，不用重复安装。
2. 在[安装页](https://aijob.zxpnb.top/install.html)点击“安装 AI 工作猎手”，确认安装。
3. 登录自己的 BOSS 账号，打开职位页或消息页并刷新，看到工具面板。

**不需要另外注册、输入激活码或自己配置 AI 服务。**登录 BOSS、连接成功后，会自动创建账号并开通内测；当前内测权限有效至 **2026 年 12 月 30 日 23:59:59（北京时间）**。

## 第一次使用

1. 在 BOSS 上传自己的 PDF 或 Word（DOCX）附件简历，再在工具面板点击“导入简历”。**导入简历是投递和自动回复前的准备，不是注册或激活。**
2. 打开“偏好设置”，检查已有内容，修改自己的目标城市、岗位方向和薪资要求，补充特殊要求后保存。
3. 先把本次投递数量设为 `1`，测试一个岗位，并到 BOSS 聊天里确认开场白和实际发送结果。
4. 想让 AI 继续回复 HR，再打开“AI 坐席”开关。使用时保持 BOSS 消息页打开、账号已登录，电脑不要休眠。

目前是测试版，真实 BOSS 账号的完整使用流程还没有全部验证。部分网络下载脚本可能慢或中断，请先确认安装成功，再测试一个岗位，不建议直接大量投递。测试结果与已知问题放在[项目状态](docs/PROJECT_STATUS_2026-10-16.md)，不会把自动检查通过当作真实账号全流程都已验证。

## 自动回复，哪些由你决定

- **总开关**：关闭“AI 坐席”后，新消息和之前没回复的消息都不会自动处理。
- **手动接管**：你手动回复某个 HR，只暂停这个聊天；想交回给 AI，就点击“恢复本会话自动回复”。
- **断线恢复**：重新登录、刷新且总开关仍开启时，会检查 HR 最后一条尚未得到你回复的消息；不是只处理刚来的新消息。
- **个人要求**：城市、薪资、电话和微信能否提供，请在偏好里写清楚；未写明的信息不应由 AI 编造。
- **重要承诺**：具体面试日期或时间、接受录用或签约，需要你本人确认，暂停只影响当前聊天。
- **营销引流**：借招聘让求职者买课、进群或拉人返佣的消息默认不回复。正常“销售”“市场推广”岗位不会只因名称而被跳过，AI 判断仍可能出错。

## 使用前请了解

本工具不是完全在你的电脑里运行。点击“导入简历”后，简历会上传服务器；使用相关功能时，解析后的简历文字、岗位、偏好和必要的聊天内容可能交给 AI 服务处理。**目前没有一键删除全部账号数据的入口，删除方式和时限尚未确定。**请在提供个人资料前阅读[个人资料如何处理](docs/DATA_FLOW_AND_RETENTION.md)。

AI 的判断和回复可能出错，不保证获得面试或工作，也不保证账号不受平台限制。遇到异常先关闭自动回复，再查看 BOSS 上的实际结果。不要把验证码、登录凭证（Cookie）或完整简历发到公开反馈区。

## 开发者怎么参与

**Issue** 用来报错、提需求或记录页面兼容性；先搜索已有问题，再写脱敏复现步骤。

**Pull Request（PR）** 是把你在自己副本里完成的代码、测试或文档修改提交给维护者审阅：

1. Fork 本仓库，在自己的副本创建分支；
2. 修改代码、文档或测试，写清实际验证结果；
3. 在 GitHub 选择 **New pull request**，将改动提交给本仓库的 `main`；
4. 维护者讨论、复核后决定是否合并。

PR 不需要单独申请“开通”。仓库允许 Fork，Issues 已开启。涉及发送、身份、权限、简历和隐私的改动必须带测试并由维护者复核。

## 开发与贡献

前端需要 Node.js 24 和 pnpm，后端需要 JDK 17 和 Maven。先按子目录说明运行测试，再提交 PR。不要把真实简历、Cookie、聊天记录、API Key、SMTP 或生产部署信息作为复现材料。

`main` 是对外源码主分支。普通贡献者不能直接写入，通过 PR 交给维护者决定是否合并。维护者自己的提交不再要求另一账号批准，但仍须通过 `frontend`、`backend` 自动检查；禁止强推和删除主分支。代码合并、服务器部署和真实账号验证是三个不同环节，不能互相替代。

计划优先处理脱敏样本、解析回归测试、UI 错误态、自部署验证和依赖可复现性。涉及发送、身份、授权和人工接管的修改必须由维护者复核。

## 自部署与数据

安装脚本默认连接维护者的托管服务，不是纯本地运行。岗位、简历文本、偏好和会话内容可能进入后端及配置的模型服务；请先阅读[数据流与保留说明](docs/DATA_FLOW_AND_RETENTION.md)。当前没有自助删除账号及其全部数据的功能，删除流程和时限尚未确认；不接受真实用户试用前，必须先建立可执行的数据删除流程并核验线上留存范围。

可拉取源码自部署，但干净机器依赖解析和真实 BOSS 流程仍未验收。当前托管服务只做小范围联调；当前版本暂不提供付费服务，历史支付代码默认关闭。扩大公开服务前仍需完成数据删除/保留策略、模型数据传输说明、SSRF/出口限制、限流/费用上限及真实账号验收。
